# Этап 2: обмен поездками

Проверка выполнена 30 сентября 2026 года. Задача — прогнать подготовленный инструмент на чужих поездках без подгонки данных, найти скрытые долги и явно вынести неопределённости в список «спорное».

Три источника содержат две разные поездки: Gist и репозиторий Александра описывают один Пекин в разных форматах. Исходники клонированы и сохранены без изменений. Авторские программы не запускались; готовые ответы не используются как вход расчёта. Собственная поездка также проверена, но её исходная таблица генератора, контрольные факты и готовые ответы остаются вне публичного репозитория.

## Что сломалось при первом прогоне

Подготовленный v1 сначала запущен без изменения кода. Он ожидал прежние пути, заголовки сообщений `### M01`, имена участников и контрольные числа собственной поездки. Для каждого набора создан изолированный каталог с прежним расположением файлов и символьной ссылкой на вход. Сам скрипт совпадал побайтно во всех прогонах.

| Набор | Код выхода | Результат без адаптации |

| Собственный | 0 | Проверка прежнего замороженного эталона прошла |
| Gist | 1 | `FileNotFoundError`: нет отдельного `chat.md`; источники внутри отчёта |
| Пекин | 1 | `AssertionError`: парсер заголовков не распознаёт 38 сообщений табличного чата |

[Сводка baseline](baseline/summary.json) сохраняет коды, ошибки и одинаковый хеш v1. Это историческое свидетельство первого прогона; код v1 и полные локальные логи сохранены приватно, поскольку содержат ответы собственной поездки. В публичной части исходный baseline повторно не запускается.

## Что изменено

Добавлен [слой нормализации](tool/normalize.py): сообщения, чеки и курсы разных форматов преобразуются в один [контракт](tool/SCHEMA.md). Поддержаны Markdown с заголовками, табличный чат с Markdown-чеками и CSV курсов, структурированный JSON и приложение источников внутри Gist. Фото R04 распознано локальным `tesseract`; авторская расшифровка из `answers/` не читается. Повторные представления одной операции объединяются, все ссылки сохраняются.

[Расчётный слой](tool/settle.py) принимает только нормализованный JSON. Формула баланса — допущенные к распределению оплаты минус доля расходов, с учётом подтверждённых переводов. Деньги считаются в целых копейках, неравные доли округляются без потери суммы. Курс выбирается на дату каждой операции; возврат пересчитывается на дату получения и проверяется в исходной валюте. Точный минимум переводов определяется через максимальное число групп с нулевой суммой, а не только жадным подбором пар. Поддерживается до 12 участников с ненулевым балансом.

Различия форматов обрабатываются адаптерами; арифметика общая. Свободный текст понимается по ограниченным явным правилам: новый формат может потребовать адаптера, нераспознанная финансовая реплика требует просмотра. Неизвестные суммы, курсы и неподтверждённые переводы не подставляются молча.

Расхождений между заявленной оплатой организатора и суммой чека в этих наборах не найдено. Такое противоречие проверено отдельным тестом: сохраняется сумма чека, обе ссылки и открытая спорная запись.

README Пекина описывает один возврат, но источники содержат два — R10 и R15. README Тбилиси говорит, что три спорных места не включены в расчёт, однако авторские контрольные числа предполагают распределение удержания поровну. Условный сценарий совпадает с ними (Аня +24 359 ₽, Глеб → Аня 3 842 ₽); это не подтверждение согласия участников.

Повторный чек Пекина R04 (фото плюс M06 и M10 «скинул чек») учтён одной операцией. Саша не платит за ужин R11, но участвует в R13, где чай взят ему с собой. В Тбилиси Ира исключена из ужина R06, Борис — из бань R10.

Нули относятся к данным. Адаптеры и общий расчётный слой написаны вручную после первого прогона. Выбор `equal-provisional` — явный сценарий, а не изменение источников.

Внутренние 16 тестов прошли, включая сверку нашей поездки с приватным эталоном. 18 публичных тестов проверяют собственные входы без ключа ответов, контрольные числа чужих наборов, разные даты курсов и возвратов, неравные доли, копейки, дубликаты, отсутствие курса, конфликт суммы, подтверждённые переводы и минимум, на котором обычный жадный план ошибается. ## Как повторить из чистой папки

Нужны Git, Python 3.10+ со стандартной библиотекой и `tesseract` с языком `eng` для фото чека. Дополнительных Python-пакетов нет. При отсутствии OCR результат помечается спорным, а регрессионная проверка фото не проходит.

```bash
git clone https://github.com/mgainanov/trip-settlement-assignments.git
cd trip-settlement-assignments
python3 stage-2/run_exchange.py --fetch
python3 stage-2/tool/test_settlement.py
```

Первый запуск клонирует исходники на зафиксированных ревизиях в `stage-2/.cache/sources/`. Повторный запуск возможен без `--fetch` и без сети. Результаты появятся в игнорируемой `stage-2/.runs/`; отчёты и JSON используют публичные ссылки на источники. Собственные ответы runner не экспортирует. Публичные тесты сравнивают пересчитанные внешние результаты с опубликованными.

Для нового набора:

```bash
python3 stage-2/tool/normalize.py ПАПКА_ДАННЫХ --output ПАПКА_РЕЗУЛЬТАТА/normalized.json
python3 stage-2/tool/settle.py ПАПКА_РЕЗУЛЬТАТА/normalized.json --output ПАПКА_РЕЗУЛЬТАТА
```

Прямой CLI сохраняет ссылки на локальные источники. Для внешних наборов из этого задания runner переводит их в URL зафиксированных ревизий; формат входа и расчёт от этого не меняются.
