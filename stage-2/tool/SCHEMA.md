# Нормализованный формат расчётов

Два отдельных шага: `normalize.py` читает источники и создаёт `normalized.json` версии 1; `settle.py` принимает только этот JSON. Расчётный слой не читает Markdown, картинки, чаты или файлы эталонов. Исходный `verify.py` сохранён неизменным в `baseline/verify-v1.py` и остаётся контрольным тестом первой поездки.

## Контракт

| Поле | Содержание |
|---|---|
| `schema_version` | 1 |
| `root` | Локальная папка исходного набора |
| `people` | Уникальный список участников и порядок распределения остаточных копеек |
| `receipts` | ID, дата ISO, плательщик или получатель возврата, точная сумма строкой, валюта, продавец, описание, участники, индивидуальные веса, родительский чек возврата и источники |
| `rates` | Валюта, дата ISO, RUB за единицу строкой и источник курса |
| `messages` | ID, дата, автор, исходный текст и ссылка на источник для аудита |
| `issues` | Неоднозначности с типом, состоянием и источниками; они не являются готовыми расходами |
| `confirmed_transfers` | Отправитель, получатель, сумма, валюта, дата, источники заявления и подтверждения |
| `pending_allocations` | Подтверждённая сумма в валюте и её дата, которую нельзя распределить без решения участников |
| `duplicates` | Повторные упоминания одной операции, не дополнительные расходы |

Возврат — отдельная операция с отрицательной суммой и явным `parent`. Конверсия выполняется по дате каждой оплаты, возврата и подтверждённого перевода. Лимит возврата проверяется в исходной валюте: из-за изменения курса полный возврат в рублях может оказаться больше исходной рублёвой оплаты. Копейки распределяются с сохранением итога методом наибольшего остатка, равные остатки — по порядку участников.

## Поддержанные входные формы

- Markdown с метаданными чеков, индивидуальными позициями и сообщениями в заголовках.
- Табличный чат с ID сообщений, Markdown-чеками и CSV курсов.
- JSON с людьми, сообщениями, чеками, возвратами и датированными курсами. Поля `disputed`, `control_facts_file` и авторские готовые решения игнорируются.
- Отчёт со специальным приложением первичных источников. Импортируется только приложение «Источники», а не таблица ответов; неполнота полного чата отмечается отдельно.
- Изображение чека через локальный `tesseract` с проверкой даты, валюты и итога. Неудача OCR становится спорной записью; скрытого ввода суммы из эталона нет.

Понимание свободного текста ограничено явными правилами. Это не универсальный анализ любой переписки. Неопознанные финансовые реплики и противоречия сохраняются для проверки; неизвестный курс не заменяется курсом другого дня. Неподдержанный формат требует нового адаптера, а не изменения арифметики.

## Сценарии

`confirmed` распределяет только однозначно согласуемые суммы. Нераспределённое удержание остаётся видимым: денежный отток равен распределённой части плюс спорная сумма. Оплаты в таблице балансов относятся к части, допущенной к распределению; фактический отток показан отдельно.

`equal-provisional` — явно условный сценарий, включающий спорное удержание поровну. Даже при совпадении с авторскими контрольными числами он не объявляется окончательным согласованным расчётом. Неизвестные расходы без суммы и неподтверждённые переводы не добавляются ни в одном сценарии.
